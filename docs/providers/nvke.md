## Delivery and ownership

This is a coverage inventory, not a support claim. Every row is reconciled in `scripts/nvke_evidence.json`.
Completion requires
a working tenant-scoped API, permission/audit mapping, UI and CLI behavior and execution evidence.
Provider transport tests alone do not prove the application integration or live NVKE behavior.

Ledger labels describe evidence scope, not completion:

- **fixture**: protocol/schema/shared wiring evidence; no native controller effect proven.
- **local**: named local execution/observation with explicit limits; no broad live support claim.
- **partial**: only some required surfaces/scenarios exist; gaps remain listed.
- **missing**: no equivalent Astro delivery found; implementation is still required.
- **unsupported**: no verified upstream implementation is exposed as supported.

- Sites belong to an Astro organization. Cross-organization site IDs answer as missing.
- Site-wide controller/operator actions require an operator permission; the controller API has
  fleet-wide access, so possession of a tenant cluster ID never authorizes such an action.
- Astro's Kubernetes-native drivers own workloads; NVKE owns node/control-plane lifecycle.
- REST, public tenant/operator APIs and management Kubernetes access are distinct connections.
  Configure and probe them independently; do not silently fall back to a stronger credential.
- Use opaque ETags/resource versions for concurrent updates and UID-preconditioned deletion.
- Accepted/provisioned is distinct from Ready. Conditions must observe the current generation.
- Authentication/TLS, secrets and upstream failures must not leak through payload or transport logs.
- Retry reads safely. A lost response to a create is ambiguous; reconcile by owned identity before retrying.
- Unsupported upstream upgrade/backup/restore behavior remains explicitly unsupported.
- Workload kubeconfig downloads require native ownership or a durable Astro creation receipt,
  matching cluster UUID labels and a live CAPI owner; see [access proofs](nvke-access.md).
