# GitHub App installation selection

GitHub installation and Astrolift registration are separate steps. Under **Providers → Source**, verify the active App connection's name and GitHub account. An installation on GitHub alone does not register that account in Astrolift, and a disabled pending connection is not used by CI.

To register another account for an existing App, choose **Connect to GitHub → Connect an existing GitHub App**. Enter that App's numeric ID and existing private key, and specify the **GitHub org / user login** that owns the repository. The login is required when the App is installed on more than one account; Astrolift does not pick one for you. Astrolift verifies the App credentials and selected installation before saving. The same App may have a separate connection for each account in one Astrolift organization. Re-adopting or rotating one account preserves the others.

For a repository such as `owner/repository`, workflow writes, webhook setup, CI secrets and manifest reads use only the active installation recorded on `owner` (the login is compared case-insensitively); an installation on another account is never used. If several are recorded on `owner`, the newest wins. If none is active, `astro ci setup <app-slug>` stops with `no active GitHub App installation for owner` and says whether the organization's connection for `owner` is inactive or missing, so reconnect or add that connection. An organization OAuth or PAT connection can still serve workflow writes, webhooks and manifest reads; CI secrets need the installation. Confirm both the App identity and account: two Apps with similar names may have different installation inventories and credentials.

Older connection records may carry stale account labels: an App created from the Astrolift manifest was recorded under its owner's login rather than the account it was installed on. Such a record now serves only repositories of the account it names. Installing through Astrolift now records the account GitHub reports. Adopting the intended App with the explicit repository owner registers its verified account and installation metadata. When replacing a different App on that account, supply that App's optional Client ID, OAuth secret and webhook secret where needed; credentials from the former App are cleared. This fixes registration; it does not grant the App additional GitHub permissions or repository access.
